# История исправлений проекта

## 🔧 Исправление #2: Gradle и Android Build (04.05.2026)

### Проблема
Проект не собирался на Android из-за конфликтов версий Gradle и зависимостей:
1. Android Gradle Plugin (AGP) версии 8.1.0 был ниже минимальной требуемой Flutter версии 8.1.1
2. Зависимости androidx требовали AGP 8.9.1 или выше
3. Конфликт версий Kotlin (2.1.0 несовместим с некоторыми плагинами)
4. Устаревший синтаксис `lintOptions` в build.gradle

### Причины
1. Устаревшая конфигурация Gradle после обновления Flutter до версии 3.41.8
2. Новые версии androidx библиотек требуют более свежий AGP
3. Несовместимость версий Kotlin с плагином shared_preferences_android

### Решение

#### 1. Обновление Android Gradle Plugin
**Файл:** `android/settings.gradle:21`
```gradle
// Было:
id "com.android.application" version "8.1.1" apply false

// Стало:
id "com.android.application" version "8.9.1" apply false
```
- AGP обновлен до 8.9.1 для совместимости с androidx зависимостями

#### 2. Обновление Kotlin
**Файл:** `android/settings.gradle:22`
```gradle
id "org.jetbrains.kotlin.android" version "2.1.0" apply false
```
- Kotlin 2.1.0 совместим с AGP 8.9.1 и Gradle 8.14

#### 3. Исправление lintOptions
**Файл:** `android/app/build.gradle:18`
```gradle
// Было:
lintOptions {
    disable 'InvalidPackage'
}

// Стало:
lint {
    disable 'InvalidPackage'
}
```
- Обновлен синтаксис для AGP 8.x

#### 4. Обновление .gitignore
**Файл:** `.gitignore`
- Добавлена папка `.claude/` (файлы Claude Code)
- Добавлены ключи подписи (`*.jks`, `*.keystore`, `key.properties`)
- Добавлены конфигурации IDE (`.settings/`, `.classpath`, `.project`)
- Структурирован по категориям (Android, iOS, Web, Windows, macOS, Linux)

### Результат
- ✅ Проект успешно собирается на Android (APK создан за 174.7 сек)
- ✅ Совместимость с Flutter 3.41.8
- ✅ Все зависимости androidx работают корректно
- ✅ Gradle 8.14 + AGP 8.9.1 + Kotlin 2.1.0
- ✅ Улучшен .gitignore (не пушаются временные файлы и ключи)

### Поддержка платформ
- ✅ **Android** - полная поддержка
- ✅ **Windows** - полная поддержка
- ✅ **Web** - полная поддержка (Chrome, Edge)
- ⚠️ **iOS** - требуется macOS для сборки
- ⚠️ **Linux** - требуется Linux система для сборки

## 🔧 Исправление #1: Зависание приложения при запуске

### Проблема
Приложение зависало на главном экране и не реагировало на нажатия. В логах видны:
- `Skipped 105/90/212 frames! The application may be doing too much work on its main thread`
- Попытки подключения к недоступному серверу `http://42.194.193.85`
- Ошибка: `type 'Null' is not a subtype of type 'Map<String, dynamic>' in type cast`

### Причины
1. При инициализации главной страницы синхронно вызывался метод `checkUpdate()`, который пытался подключиться к серверу для проверки обновлений. Это блокировало UI поток на время таймаута (10 секунд).
2. При парсинге задач из базы данных не обрабатывался случай, когда `textColor` после декодирования JSON может быть `null`.

### Решение

#### 1. Асинхронный вызов проверки обновлений
**Файл:** `lib/model/main_page_model.dart:74-93`
- Перенесён вызов `logic.checkUpdate(globalModel)` в `Future.microtask()` 
- Теперь проверка обновлений не блокирует инициализацию UI

#### 2. Улучшенная обработка ошибок
**Файл:** `lib/logic/main_page_logic.dart:502-556`
- Добавлен `try-catch` для перехвата исключений
- Добавлена проверка `context.mounted` перед показом диалога обновления
- Обработка ошибок при получении версии пакета

#### 3. Уменьшены таймауты сетевых запросов
**Файл:** `lib/config/api_strategy.dart:14-15`
- Таймаут подключения: 10 → 5 секунд
- Таймаут получения ответа: 15 → 10 секунд

#### 4. Исправлен парсинг textColor
**Файл:** `lib/json/task_bean.dart:144-152`
- Добавлена проверка на `null` после декодирования JSON
- Добавлена проверка типа перед приведением к `Map<String, dynamic>`

### Результат
- ✅ Приложение запускается мгновенно, даже если сервер недоступен
- ✅ UI не блокируется сетевыми запросами
- ✅ Проверка обновлений выполняется в фоне
- ✅ Нет ошибок при загрузке задач из базы данных
- ✅ Улучшена отзывчивость интерфейса
