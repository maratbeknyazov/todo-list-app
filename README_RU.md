### Структура проекта

Фреймворк управления состоянием, используемый в проекте, это <code>Provider</code>, и архитектура всего проекта выглядит следующим образом

![image](https://user-images.githubusercontent.com/30992818/62599801-c4e55780-b91f-11e9-8acd-5173bc5f6f38.png)

- Слой View используется для отображения макетов и представляет собой различные страницы **StatelessWidget**, обернутые в **ChangeNotifierProvider**
- Слой Model используется для обработки данных и представляет собой различные классы Model, наследующие **ChangeNotifier**
- Слой Logic не сохраняет никаких данных, только логические операции



Похоже на паттерн **MVP** в Android? На самом деле они все похожи, но названия немного отличаются. Вы также можете думать о вышеуказанном режиме как о режиме MVP.


Flutter особенно хорошо подходит для этой архитектурной модели, потому что представление изменяется вместе с данными, вам в основном не нужно заботиться о View, просто работайте с данными.

### Структура директорий

Структура директорий проекта выглядит следующим образом:

```
├── android
├── build
├── images
├── intl.sh
├── ios
├── lib
├── local_json
├── pubspec.lock
├── pubspec.yaml
├── res
├── svgs
├── test
└── todo_list.iml

```


Позвольте мне объяснить другие директории помимо **lib**:

директория | описание
---|---
images | Для хранения различных изображений
local_json | Я инкапсулирую информацию об иконках Flutter в Json файл и храню его в этой директории
res | Хранение языковых файлов, сгенерированных плагином "intl"
svgs | Хранение изображений в формате svg

Затем директория lib


![image](https://user-images.githubusercontent.com/30992818/62599609-41c40180-b91f-11e9-81a2-dd297c8c56aa.png)



директория | описание
---|---
config | Хранение различных классов конфигурации, таких как класс инкапсуляции запросов Dio и т.д.
database | Хранение классов, связанных с операциями базы данных
i10n | Класс для хранения операций, связанных с интернационализацией
items | Класс Item, который хранит часть списка List
json | Различные json файлы, связанные с сетевыми запросами, базами данных и т.д.
logic | Директория слоя Logic
model | Директория слоя Model
pages | Хранение каждой страницы, это директория слоя View
utils | Упакованные инструменты, такие как операции с файлами
widgets | пользовательские виджеты
